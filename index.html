How it works

Data flow

  • iCal sync (Booking.com, every 2h) → Reservations sheet.
  • Apartments Live board: host toggles checkboxes per unit/day/task.
  • on-edit trigger → AMS_syncApartmentsToTasks → Tasks sheet (add on check, precise delete on uncheck).
  • Daily 07:00 trigger → builds each worker's schedule → posts to Telegram group (DM per worker when a chat id exists).
  • Week View rebuilt every Monday from Tasks.

Control surfaces

  • Apps Script editor — run any function directly.
  • Telegram group bot — /run <function> executes deployed functions.

Key rule: never modify columns A/B/C on Apartments Live — only toggle task checkboxes. The A/B/C layout is protected by design.

How to operate

Run in the editor

  • AMS_setupWorkers() — register the 8 workers (run once).
  • AMS_iCalSync() — pull Booking.com reservations now.
  • AMS_syncApartmentsToTasks() — rebuild Tasks from the board.
  • AMS_dedupeTasks() — collapse duplicate Tasks rows.
  • AMS_buildWeekView() — rebuild the week sheet.
  • AMS_installTriggers() — (re)install on-edit + time triggers.

Telegram commands

  • /ping — health check.
  • /ical — sync iCal now.
  • /week / /tasks — boards.
  • /today — today's agenda.
  • /done <taskId> — mark complete.
  • /run <function> — run any allowed function.
Known limitations
  • HTTP Bridge is unreachable. clasp deploy only produces API-executable deployments (all return 404 on /exec), so the spreadsheet cannot be read remotely. The bridge has a readSheet action ready for when a real web-app deployment is created from the Apps Script editor.
  • Worker DMs need each worker's Telegram @username / chat id filled into the telegram column of the Workers sheet.
  • More listings need the iCal feed URLs for Apartment 1/2 and Moerbeke.
Codebase (file map)

  • TasksOps.js — /today, /done, daily push.
  • Notify.js — worker directory (AMS_readWorkers), AMS_normName tolerant matcher, AMS_setupWorkers, DM/group send.
